# Daily Kit returns and admin receipt

When a job is cancelled, issued equipment and materials remain with the technician. Cancellation does not restore physical stock or mean that nothing was used.

Technicians use **My tools** to report reusable equipment as used or unused, with its condition. The **Materials and returns** section lists all outstanding issued consumables and repair parts, including past work dates. Its counters distinguish recorded usage from quantities not yet accounted for. Reports can cover unused, additional used, damaged, and missing quantities. Additional usage must not duplicate usage already recorded on the job.

Technicians can select materials across pages and choose **Return selected**, or choose **Return all** to preview every available material, skipping items already awaiting receipt. The preview starts with the available quantity marked unused; technicians check and adjust each breakdown before submitting. Up to 100 materials can be submitted together. Larger lists require selecting smaller batches rather than silently returning only part of the list. Each batch reserves its quantities in one transaction: an invalid item, changed balance, pending report, or ownership mismatch rolls back the whole submission. Each item remains a separate report for admin receipt. No stock is credited by submitting a batch.

Admin uses **Inventory → Equipment Returns → Kit returns awaiting receipt**. Admin checks the items, corrects the breakdown if necessary, and confirms receipt. A report can instead be rejected with a correction note. Secretaries can view the reports but cannot confirm stock receipts.

Admin can select pending reports across pages and choose **Review selected**, or use **Review all** to preview all pending reports. The batch dialog includes technician names, linked jobs, reported notes, editable material quantities, equipment conditions, and optional notes for each item. Receipt requires confirming that the items were checked. **Needs correction** requires a reason for every selected report, using individual notes or a shared note. Up to 100 reports can be reviewed together. Receipts and rejections run as one transaction: a stale report or invalid quantity rolls back every selected review. Original technician quantities, admin review details, audit entries, and private technician notifications are retained. Completed reviews clear the selection and move pagination back to a valid page when the pending list shrinks. Secretary views omit receipt controls; the API also enforces admin-only batch review.

Only usable returned quantities are added to available stock. Used, damaged, and missing quantities are recorded without a stock credit. Pending quantities cannot also be consumed on another job. Tools still required by unfinished linked work cannot be returned as usable equipment. Original issue links and settled kit rows are retained across regeneration.

Receipt changes run in a MongoDB transaction. Report status, kit balances, project material ledgers, stock, and material stock-history entries commit together. Repeated receipt requests cannot credit the same report twice. Legacy technician and project return routes now submit reports rather than restoring stock directly. Admin's existing equipment reconciliation action uses the same transactional receipt service.

The Inventory sidebar counts the union of overdue equipment and equipment awaiting receipt, plus pending material reports. Equipment that is both overdue and awaiting receipt is counted once. New reports notify admin; review results notify only the owning technician. Visible pages refresh on relevant events and periodically to recover missed events.

Verification: focused unit and route checks cover ownership, admin-only receipt, shared jobs, cancellation, conservation of quantities, partial returns, duplicate submissions, failed receipt rollback, kit history, and usage while a return is pending. Local Edge checks use mocked requests to verify the technician and admin dialogs at a narrow viewport: scrolling, visible footer, receipt checkbox, exact submitted quantities, and one request per repeated click. No production stock was changed for verification.
